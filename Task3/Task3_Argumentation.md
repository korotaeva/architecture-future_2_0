## Роадмап преобразований

*(Роадмап отрисован в виде временной шкалы в Draw.io и сохранен как `Future_2_0_Roadmap.png`)*

**Этапы:**

1.  **Квартал 1: Фундамент и пилот (3 месяца)**
    *   **Цель:** Сформировать кросс-функциональную рабочую группу, выбрать и развернуть пилотную технологическую платформу (K8s, Kafka, Airflow), разработать стандарты взаимодействия.
    *   **Результат:** Готовность платформы для миграции первого домена. Первый data product от пилотного домена (напр., "Финтех").
    *   **Ответственные:** Архитекторы, DevOps, ведущие разработчики из всех доменов.

2.  **Квартал 2-3: Миграция "Финтеха" и построение Data Lake (6 месяцев)**
    *   **Цель:** Выделить домен "Финтех" в независимые сервисы. Настроить выгрузку его данных через API и в новый Data Lake. Начать перенос ETL-процессов с Legacy DWH на Airflow.
    *   **Результат:** "Финтех" работает независимо. Первые отчеты строятся на основе данных из Data Lake, а не напрямую из Legacy DWH.
    *   **Ответственные:** Команда "Финтеха", Data-инженеры.

3.  **Квартал 4: Подключение домена "Клиники" и запуск Портала (3 месяца)**
    *   **Цель:** Подключить домен "Клиники" по той же схеме. Разработать и запустить MVP Портала самообслуживания с доступом к данным из обоих доменов и Data Lake.
    *   **Результат:** Бизнес-пользователи начинают использовать новый портал для построения отчетов. Нагрузка на Legacy DWH начинает снижаться.
    *   **Ответственные:** Команда "Клиник", BI-разработчики, фронтенд-разработчики портала.

4.  **Квартал 5-6: Оптимизация и вывод из эксплуатации (6 месяцев)**
    *   **Цель:** Подключить домен "ИИ-Сервисы". Перенести все критические отчеты на новую платформу. Начать процесс полного вывода Legacy DWH из эксплуатации.
    *   **Результат:** Legacy DWH отключен. Все направления работают в новой архитектуре. Портал самообслуживания — основное средство для аналитики.
    *   **Ответственные:** Все команды.

## Обоснование этапов роадмапа

*   **Этап 1 (Фундамент):** Без общей платформы и стандартов дальнейшая работа превратится в хаос. Этот этап закладывает основу для всего последующего развития и позволяет отработать методику на пилоте без риска для основных бизнес-процессов.
*   **Этап 2 (Миграция "Финтеха"):** "Финтех" — относительно более молодой и технологически продвинутый домен (Golang/Java). Его проще отделить первым. Успешная миграция одного домена докажет жизнеспособность подхода и даст ценный опыт для команд.
*   **Этап 3 (Подключение "Клиник"):** Это ядро бизнеса, миграция сопряжена с высокими рисками. К этому моменту платформа уже будет обкатана на "Финтехе", что снизит риски. Запуск портала на реальных данных покажет бизнесу окупаемость инвестиций.
*   **Этап 4 (Оптимизация и вывод):** Финальная стадия, на которой новая архитектура полностью доказывает свое превосходство. Вывод из эксплуации устаревшего и дорогого в поддержке Legacy DWH — ключевая финансовая цель проекта.
